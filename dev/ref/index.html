StandardHaloModelsPP.SHMerr — Constant

SHM with measurement uncertainties on its two characteristic speeds included, for sensitivity studies of Halo Model conventions and uncertainties.

SHMerr
Local DM density$\rho_0$$0.3\text{ GeV}\text{ cm}^{-3}$ (fixed)
Circular rotation speed$v_0$$238.0 \pm 1.5\text{ km}\text{ s}^{-1}$
Escape speed$v_\text{esc}$$544 \pm 33\text{ km}\text{ s}^{-1}$
  • v₀: using uncertainty quoted but not used in [2, Sec. 3.1.5].
  • vₑ: using the RAVE 90% confidence interval $498 < v_\text{esc} < 608$ km/s of [7] (median 544 km/s, agreeing with the SHM convention), symmetrized and converted to $1\sigma$: $(608 - 498) / (2 \times 1.645) \approx 33$ km/s.
  • ρ₀ is a fixed value rather than a measurement with uncertainty, as it is not a directly measured quantity; set another value (usually in the range 0.2-0.6 GeV/cm³) by creating your own HaloModel from this one via HaloModel.
  • $v_\text{LSR} = v_0$ as Measurements.jl objects so the dispersion and the boost are correctly correlated.
Note

[2, Sec. 3.1] recommends against attaching uncertainties to the SHM parameters when reporting results: they "do not accurately reflect the uncertainties in the dark matter halo, nor do they represent likelihood distributions that can be meaningfully profiled over". SHM therefore stays exact (and is the default model); use SHMerr for sensitivity studies, but not for reporting limits. Propagating Measurements uncertainties also has a significant performance impact on integrals.

Reference circular speed of the Local Standard of Rest (LSR), used by ephemeris functions when no model is given.

Value: 238.0 ± 1.5 km s^-1

D. Baxter and others, Eur. Phys. J. C 81, 907 (2021); Sec. 3.1.5.

A HaloModel carries its own LSR speed m.VLSR, which by default is its circular speed v₀. StandardHaloModelsPP.HaloIntegralProblem — Type
HaloIntegralProblem([m::HaloModel = SHM,] [t::TimeLike = T0,] kk; measure = :velocity, uncertainty = false, kwargs...)

An integral problem with a kernel kk against the lab-frame velocity distribution of m at time t, set up for Integrals.jl. The kernel kk may be any callable (a function, or a callable object) taking (v, p) or just (v): with the default p = () it is called as kk(v) if it has a method for that (so norm or inv ∘ norm work), otherwise as kk(v, ()); with a p, as kk(v, p) if it has a method for that, otherwise as kk(v). solve it with any Integrals.jl algorithm:

using LinearAlgebra: norm
using Integrals: HCubatureJL
using Dates: DateTime, Day

prob = HaloIntegralProblem(SHM, v -> 1 / norm(v); vmin = 300u"km/s")
sol = solve(prob)
sol = solve(prob, HCubatureJL(); reltol = 1e-6, maxiters = 10^6)
sol.u                                     # integral solution with units
remake(prob; t = T0 + Day(90))            # integral at another time

Measures

  • measure = :velocity: $\int_{v>v_\text{min}} f_{\chi,\text{lab}}(\mathbf{v})\, k(\mathbf{v}, p)\,d^3v$, with kk(v::AbstractVector, p). Keywords: vmin, p. The problem is 3D over rescaled spherical coordinates $(s, w, \alpha) \in [0,1] \times [0,1] \times [0,2\pi]$, polar about the Earth's velocity, spanning exactly the distribution's support above $v_\text{min}$: the escape-speed boundary is the domain boundary, and near $v_\text{max}$ the domain shrinks onto the small cap of directions that still reach it; default algorithm HCubatureJL(), reltol = 1e-4, abstol = 0. See velint.

  • measure = :speed: $\int_{v_\text{min}}^{v_\text{max}} k(v, p)\, f_{\chi,\text{lab}}^{\text{speed}}(v)\,dv$, with kk(v::Unitful.Velocity, p). Keywords: vmin, vmax (default $v_\text{esc} + V_E$), p, analytic, and the inner angular quadrature's inneralg, innerreltol (1e-7), innerabstol (0). The problem is 1D over $v$; the inner integral, fχspeed, is fixed at construction, and is analytic when $\eta = 0$ and $V_E < v_\text{esc}$. Default algorithm QuadGKJL(), reltol = 1e-6, abstol = 0. See speedint.

Solving

solve(prob[, alg]; reltol, abstol, kwargs...) returns a HaloIntegralSolution; further kwargs go to Integrals.jl's solve. abstol may be a Quantity in the units of the result; a plain number is taken in the integrand's internal (unit-stripped) units. remake(prob; kwargs...) rebuilds the problem with any constructor argument changed (m, t, kernel, measure, uncertainty, or the measure's keywords), at a few percent of the cost of a solve.

Sweeps

A sweep is a SciML EnsembleProblem whose prob_func remakes the problem per point; it returns an EnsembleSolution of HaloIntegralSolutions, and runs on threads with EnsembleThreads() (start Julia with -t auto):

ts = [DateTime(2020, 1, 1) + Day(d) for d in 0:364]
ens = EnsembleProblem(prob; prob_func = (p, ctx) -> remake(p; t = ts[ctx.sim_id]))
sols = solve(ens, nothing, EnsembleThreads(); trajectories = length(ts))

Pass nothing as the algorithm for the problem's default. Kernel parameters sweep the same way, e.g. remake(p; p = Es[ctx.sim_id]) for a kernel kk(v, p).

Uncertainties

By default only the central values of m's parameters (and of the ephemeris) are integrated. uncertainty = true additionally propagates a Measurement model's uncertainties. That is typically 10-130x slower, and only works with pure-Julia algorithms (e.g. QuadGKJL, HCubatureJL): C-backed ones (Cuba, Cubature) need plain floating-point integrands. The defaults measure error on central values (norm = value ∘ norm); a user-supplied adaptive algorithm without that norm still works, but possibly more slowly.

StandardHaloModelsPP.HaloModel — Type
HaloModel(ρ₀::Union{Unitful.Pressure,Unitful.Density}, v₀::Unitful.Velocity, vₑ::Unitful.Velocity, β::Real, η::Real[, VLSR::Unitful.Velocity])

An SHM++-parameterized halo model, per the definition in N. Wyn Evans, Ciaran A.J. O'Hare, Christopher McCabe, Phys. Rev. D. 99, 023012 (2019) (arXiv).

  • localdensity: ρ₀, local DM mass density: with mass in energy units (e.g. u"GeV/cm^3", hence a Unitful pressure), or as a mass density (e.g. UnitfulAstro: u"Msun/pc^3"); units are stored as given.

  • circspeed: v₀, circular speed of the flat asymptote of the galactic rotation curve, which sets the DM velocity dispersion $\sigma = v_0 / \sqrt{2}$.

  • escspeed: vₑ, galactic escape speed.

  • anisotropy: β, Gaia sausage anisotropy, 0 ≤ β < 1.

  • sausagefrac: η, Gaia sausage prominence, 0 ≤ η ≤ 1.

  • lsrspeed: VLSR, speed of the Local Standard of Rest, which sets the boost to the lab frame. By default (omitted, or nothing) it is v₀: the SHM's isothermal halo has a flat rotation curve with circular speed $v_0 = \sqrt{2}\sigma$, so the two coincide [5]. Give it to boost with a different speed than the dispersion implies. m.VLSR is always the speed in use, even when tied to v₀.

StandardHaloModelsPP.fR — Method
fR([m::HaloModel = SHM,] v::AbstractVector{<:Unitful.Velocity})
fR([m::HaloModel = SHM,] v::Unitful.Velocity)
fR(m::HaloModel) -> v -> fR(m, v)

Galactic-frame Maxwellian component of $f_\chi$.

$f_R(\mathbf{v}) = \frac{1}{(2\pi\sigma_v^2)^{3/2}N_{R,\text{esc}}} \exp\left(-\frac{|\mathbf{v}|^2}{2\sigma_v^2}\right)\Theta(v_\text{esc} - |\mathbf{v}|)$

$N_{R,\text{esc}} = \text{erf}\left(\frac{v_\text{esc}}{\sqrt{2}\sigma_v}\right) - \sqrt{\frac{2}{\pi}}\frac{v_\text{esc}}{\sigma_v}\exp\left(-\frac{v_\text{esc}^2}{2\sigma_v^2}\right)$

with $\sigma_v = v_0/\sqrt{2}$. Isotropic, so v may be given as a scalar speed.

For fR(m) see "Repeated evaluation" under fχ.

StandardHaloModelsPP.fS — Method
fS([m::HaloModel = SHM,] v::AbstractVector{<:Unitful.Velocity})
fS(m::HaloModel) -> v -> fS(m, v)

Galactic-frame anisotropic (Gaia sausage) component of $f_\chi$.

$f_S(\mathbf{v}) = \frac{1}{(2\pi)^{3/2}\sigma_r\sigma_\theta^2 N_{S,\text{esc}}} \exp\left(-\frac{v_r^2}{2\sigma_r^2} - \frac{v_\theta^2}{2\sigma_\theta^2} - \frac{v_\phi^2}{2\sigma_\phi^2}\right) \Theta(v_\text{esc} - |\mathbf{v}|)$

$N_{S,\text{esc}} = \text{erf}\left(\frac{v_\text{esc}}{\sqrt{2}\sigma_r}\right) - \sqrt{\frac{1-\beta}{\beta}} \exp\left(-\frac{v_\text{esc}^2}{2\sigma_\theta^2}\right)\text{erfi}\left(\frac{v_\text{esc}}{\sqrt{2}\sigma_r}\sqrt{\frac{\beta}{1-\beta}}\right)$

Anisotropic, so v must be a vector; v[1] is the radial (sausage) axis $v_r$.

For fS(m) see "Repeated evaluation" under fχ.

StandardHaloModelsPP.fχ — Method
fχ([m::HaloModel = SHM,] v::AbstractVector{<:Unitful.Velocity})
fχ(m::HaloModel) -> v -> fχ(m, v)

Galactic-frame SHM++ velocity distribution: a mixture of the round fR and anisotropic fS components.

$f_\chi(\mathbf{v}) = (1 - \eta) f_R(\mathbf{v}) + \eta f_S(\mathbf{v})$

Repeated evaluation

Each fχ(m, v) call recomputes the model's normalizations (erf, erfi and exp of the parameters), which for a Measurement model costs several times the evaluation itself.

The one-argument form f = fχ(m) computes them once and returns a callable f(v), to use in hot loops, closures or integrands. Broadcasting over velocities with a single model, as in fχ.(m, vs) or fχ.(vs), does this automatically.

The same applies to fR, fS, fRlab and fχlab.

StandardHaloModelsPP.fχspeed — Method
fχspeed(m::HaloModel, t::TimeLike; uncertainty = false, analytic = true, alg = HCubatureJL(), reltol = 1e-4, abstol = 0, kwargs...) -> v -> fχspeed(m, t, v)
fχspeed([m::HaloModel = SHM,] [t::TimeLike = T0,] v::Unitful.Velocity; uncertainty = false, analytic = true, alg = HCubatureJL(), reltol = 1e-4, abstol = 0, kwargs...)

Marginalized speed distribution, integrated over solid angle:

\[f_{\chi,\text{lab}}^{\text{speed}}(v) = v^2\int f_{\chi,\text{lab}}(\mathbf{v})\, d\Omega\]

normalized so $\int f\,dv = 1$.

When $\eta = 0$ and the Earth is inside the escape sphere ($V_E < v_\text{esc}$, true of all preset models) an exact analytic form [16, Sec. I.4] is used; pass analytic=false to force numerical integration. abstol defaults to 0, a purely relative tolerance. It may be a Quantity in the units of the result; a plain number is taken in the integrand's internal (unit-stripped) units. Further kwargs are passed to Integrals.jl's solve.

By default the central values of m's parameters (and of the ephemeris) are integrated. Pass uncertainty = true to propagate a Measurement model's uncertainties (typically 10-130x slower due to derivative tracking/propagation).

The two-argument form fχspeed(m, t) returns the distribution at t as a callable v -> fχspeed(m, t, v), with the lab frame, normalizations and the analytic-or-numerical choice fixed. Use it to evaluate repeatedly, e.g. inside your own integrand. It does not warn on non-convergence per evaluation (check caller's outer integral instead).

See also fχplanar for the marginalization over $v_z$.

StandardHaloModelsPP._capangle — Method
_capangle(Q, VEn, vmin) -> γ0

Polar angle from V̂ beyond which a lab-frame direction n̂ has support at some speed v ≥ vmin, i.e. |v n̂ + V| < vₑ; all of the integrand's support lies in γ ∈ [γ0, π].

Q = vₑ² - |V|², VEn = |V|, vmin the kinematic lower cutoff. Along n̂ at angle γ the condition is cos γ < (Q - v²)/(2v|V|), largest at v = max(vmin, √(-Q)).

StandardHaloModelsPP._velocityproblem — Method
_velocityproblem(m::HaloModel, t, kk; vmin = 0u"km/s", p = ())

Construct the 3D velocity integrand over (s, w, α) ∈ [0,1] × [0,1] × [0,2π].

Kernel kk receives (vxyz, vv, p) with vv = norm(vxyz).

Returns the unit-free problem and the unit of its integral. As in _fχspeed, directions n̂ are polar about V̂, at angle γ, and restricted to the cap γ ∈ [γ0, π] holding all the support above vmin (see _capangle), rescaled onto w ∈ [0,1]; α is the full azimuth, since the kernel need not be symmetric. The radial coordinate is rescaled onto s ∈ [0,1] spanning the support [lo, lo + Δ] along n̂. So the domain is the support, and adaptive cubature can't miss even a small cap near vmaxlab.

The support along n̂ shrinks to nothing at γ0, where the integrand vanishes, so the central-value bound γ0 needs no first-order boundary term for Measurement models.
