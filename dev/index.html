Introduction - Galactic-Frame Velocity Distributions

StandardHaloModelsPP.jl implements Dark Matter velocity distributions, and integrals of them, for the Standard Halo Model (SHM) and an extension of the distribution, the SHM++. The SHM is an isotropic, truncated Maxwellian [1]; by default its parameters follow the recommended conventions for reporting direct-detection results [2]. The SHM++ adds an anisotropic component to better model local measurements, accounting for the "Gaia Sausage" [3, 4], as defined by:

[5]: N. Wyn Evans, Ciaran A.J. O'Hare, Christopher McCabe, Phys. Rev. D. 99, 023012 (2019) (arXiv:1810.11468)

A HaloModel struct encodes the SHM++ parameterization, and Presets are provided for common choices. This page covers the galactic-frame distributions; their lab-frame counterparts and integrals follow.

StandardHaloModelsPP.HaloModel — Type
HaloModel(ρ₀::Union{Unitful.Pressure,Unitful.Density}, v₀::Unitful.Velocity, vₑ::Unitful.Velocity, β::Real, η::Real[, VLSR::Unitful.Velocity])

An SHM++-parameterized halo model, per the definition in N. Wyn Evans, Ciaran A.J. O'Hare, Christopher McCabe, Phys. Rev. D. 99, 023012 (2019) (arXiv).

  • localdensity: ρ₀, local DM mass density: with mass in energy units (e.g. u"GeV/cm^3", hence a Unitful pressure), or as a mass density (e.g. UnitfulAstro: u"Msun/pc^3"); units are stored as given.

  • circspeed: v₀, circular speed of the flat asymptote of the galactic rotation curve, which sets the DM velocity dispersion $\sigma = v_0 / \sqrt{2}$.

  • escspeed: vₑ, galactic escape speed.

  • anisotropy: β, Gaia sausage anisotropy, 0 ≤ β < 1.

  • sausagefrac: η, Gaia sausage prominence, 0 ≤ η ≤ 1.

  • lsrspeed: VLSR, speed of the Local Standard of Rest, which sets the boost to the lab frame. By default (omitted, or nothing) it is v₀: the SHM's isothermal halo has a flat rotation curve with circular speed $v_0 = \sqrt{2}\sigma$, so the two coincide [5]. Give it to boost with a different speed than the dispersion implies. m.VLSR is always the speed in use, even when tied to v₀.

StandardHaloModelsPP.HaloModel — Method
HaloModel(; ρ₀, v₀, vₑ, β = 0, η = 0, VLSR = nothing)
HaloModel(m::HaloModel; kwargs...)

Keyword forms of the HaloModel constructor. Each parameter may be named by its field name or a symbol shorthand (v₀ or circspeed, vₑ or escspeed, ...).

Also a copying form which copies m with the given parameters changed, e.g. HaloModel(SHMpp; v₀ = 220u"km/s"). Unchanged Measurement parameters are carried over as the same objects to maintain correlations.

This also allows e.g. Accessors.jl to work automatically on symbol shorthands: @set SHMpp.v₀ = 220u"km/s".

source

Every function takes a model as an optional first argument, defaulting to the SHM (e.g. fχ(v) == fχ(SHM, v)), and every lab-frame function an optional time after it, defaulting to T0 (June 1st.).

Physical Units

Quantities carry units using Unitful.jl, as re-exported by NaturallyUnitful.jl: densities in e.g. u"GeV/cm^3", speeds in e.g. u"km/s". Any compatible units are accepted, so e.g. you may use UnitfulAstro.jl.

Lab-frame boosts (see more on Ephemerides) use the LSR speed $v_\text{LSR} = v_0$ by default. Other models can be built with the HaloModel constructors: e.g. HaloModel(SHM; vₑ = 500u"km/s"), or with a different LSR speed, HaloModel(SHMpp; VLSR = 238u"km/s").

The Standard Halo Model

The SHM presets follow the conventions of [2, Table 1], with the historical $v_0 = 220$ km/s variant of [5, Table I], an untruncated variant, and a variant with measurement uncertainties:

StandardHaloModelsPP.SHM — Constant

The default HaloModel for the SHM, following the recommended conventions for reporting direct-detection results in D. Baxter et al., Eur. Phys. J. C 81, 907 (2021) (arXiv)

SHM
Local DM density$\rho_0$$0.3\text{ GeV}\text{ cm}^{-3}$
Circular rotation speed$v_0$$238\text{ km}\text{ s}^{-1}$
Escape speed$v_\text{esc}$$544\text{ km}\text{ s}^{-1}$
Velocity distribution$f_R(\mathbf{v})$Gaussian

(additional SHM++ parameters are zeroed.) [2, Table 1]

v₀, and so the LSR speed of the lab-frame boost, is the reference ephemeris' VLSR (its central value). For the pre-2021 v₀ = 220 km/s convention see SHMlegacy.

StandardHaloModelsPP.SHMnoesc — Constant

An untruncated variant of SHM: vₑ = Inf, so the Maxwellian has no escape-speed cutoff and normalizes to unity over all velocities.

source
StandardHaloModelsPP.SHMerr — Constant

SHM with measurement uncertainties on its two characteristic speeds included, for sensitivity studies of Halo Model conventions and uncertainties.

SHMerr
Local DM density$\rho_0$$0.3\text{ GeV}\text{ cm}^{-3}$ (fixed)
Circular rotation speed$v_0$$238.0 \pm 1.5\text{ km}\text{ s}^{-1}$
Escape speed$v_\text{esc}$$544 \pm 33\text{ km}\text{ s}^{-1}$
  • v₀: using uncertainty quoted but not used in [2, Sec. 3.1.5].
  • vₑ: using the RAVE 90% confidence interval $498 < v_\text{esc} < 608$ km/s of [7] (median 544 km/s, agreeing with the SHM convention), symmetrized and converted to $1\sigma$: $(608 - 498) / (2 \times 1.645) \approx 33$ km/s.
  • ρ₀ is a fixed value rather than a measurement with uncertainty, as it is not a directly measured quantity; set another value (usually in the range 0.2-0.6 GeV/cm³) by creating your own HaloModel from this one via HaloModel.
  • $v_\text{LSR} = v_0$ as Measurements.jl objects so the dispersion and the boost are correctly correlated.
Note

[2, Sec. 3.1] recommends against attaching uncertainties to the SHM parameters when reporting results: they "do not accurately reflect the uncertainties in the dark matter halo, nor do they represent likelihood distributions that can be meaningfully profiled over". SHM therefore stays exact (and is the default model); use SHMerr for sensitivity studies, but not for reporting limits. Propagating Measurements uncertainties also has a significant performance impact on integrals.

Its velocity distribution is a Maxwellian truncated at the escape speed [5, Eqs. (1, 2)]:

StandardHaloModelsPP.fR — Method
fR([m::HaloModel = SHM,] v::AbstractVector{<:Unitful.Velocity})
fR([m::HaloModel = SHM,] v::Unitful.Velocity)
fR(m::HaloModel) -> v -> fR(m, v)

Galactic-frame Maxwellian component of $f_\chi$.

$f_R(\mathbf{v}) = \frac{1}{(2\pi\sigma_v^2)^{3/2}N_{R,\text{esc}}} \exp\left(-\frac{|\mathbf{v}|^2}{2\sigma_v^2}\right)\Theta(v_\text{esc} - |\mathbf{v}|)$

$N_{R,\text{esc}} = \text{erf}\left(\frac{v_\text{esc}}{\sqrt{2}\sigma_v}\right) - \sqrt{\frac{2}{\pi}}\frac{v_\text{esc}}{\sigma_v}\exp\left(-\frac{v_\text{esc}^2}{2\sigma_v^2}\right)$

with $\sigma_v = v_0/\sqrt{2}$. Isotropic, so v may be given as a scalar speed.

For fR(m) see "Repeated evaluation" under fχ.

Anisotropic Refinement - the SHM++

The SHM++ adds two parameters for the so-called "Gaia Sausage", its anisotropy $\beta$ and its fraction $\eta$ of the local DM [5, Table I]:

StandardHaloModelsPP.SHMpp — Constant

The default HaloModel for the SHM++.

SHM++
Local DM density$\rho_0$$0.55 \pm 0.17\text{ GeV}\text{ cm}^{-3}$
Circular rotation speed$v_0$$233 \pm 3\text{ km}\text{ s}^{-1}$
Escape speed$v_\text{esc}$$528 \pm 25\text{ km}\text{ s}^{-1}$
Sausage anisotropy$\beta$$0.9\pm 0.05$
Sausage fraction$\eta$$0.2\pm 0.1$
Velocity distribution$f_\chi(\mathbf{v})$Gaussian+Sausage

[6, Table 1]

As in the defining SHM++ paper, the lab-frame boost uses $v_\text{LSR} = v_0 = 233 \pm 3$ km/s, with the boost and the dispersion correlated. Create your own modified copy if you want a SHM++ halo model with Baxter [2] parameters instead.

You may want to strip Measurement uncertainties via Measurements.value(m) if you are not interested in sensitivity questions wrt. the Gaia sausage and just want to use this as a halo model.

source

Its distribution mixes the round SHM component $f_R$ with the anisotropic sausage component $f_S$ [5, Eq. (3)]:

StandardHaloModelsPP.fχ — Method
fχ([m::HaloModel = SHM,] v::AbstractVector{<:Unitful.Velocity})
fχ(m::HaloModel) -> v -> fχ(m, v)

Galactic-frame SHM++ velocity distribution: a mixture of the round fR and anisotropic fS components.

$f_\chi(\mathbf{v}) = (1 - \eta) f_R(\mathbf{v}) + \eta f_S(\mathbf{v})$

Repeated evaluation

Each fχ(m, v) call recomputes the model's normalizations (erf, erfi and exp of the parameters), which for a Measurement model costs several times the evaluation itself.

The one-argument form f = fχ(m) computes them once and returns a callable f(v), to use in hot loops, closures or integrands. Broadcasting over velocities with a single model, as in fχ.(m, vs) or fχ.(vs), does this automatically.

The same applies to fR, fS, fRlab and fχlab.

with the sausage [5, Eqs. (5-7)]:

StandardHaloModelsPP.fS — Method
fS([m::HaloModel = SHM,] v::AbstractVector{<:Unitful.Velocity})
fS(m::HaloModel) -> v -> fS(m, v)

Galactic-frame anisotropic (Gaia sausage) component of $f_\chi$.

$f_S(\mathbf{v}) = \frac{1}{(2\pi)^{3/2}\sigma_r\sigma_\theta^2 N_{S,\text{esc}}} \exp\left(-\frac{v_r^2}{2\sigma_r^2} - \frac{v_\theta^2}{2\sigma_\theta^2} - \frac{v_\phi^2}{2\sigma_\phi^2}\right) \Theta(v_\text{esc} - |\mathbf{v}|)$

$N_{S,\text{esc}} = \text{erf}\left(\frac{v_\text{esc}}{\sqrt{2}\sigma_r}\right) - \sqrt{\frac{1-\beta}{\beta}} \exp\left(-\frac{v_\text{esc}^2}{2\sigma_\theta^2}\right)\text{erfi}\left(\frac{v_\text{esc}}{\sqrt{2}\sigma_r}\sqrt{\frac{\beta}{1-\beta}}\right)$

Anisotropic, so v must be a vector; v[1] is the radial (sausage) axis $v_r$.

For fS(m) see "Repeated evaluation" under fχ.

The Galactic-Frame Distribution

fχ is the full galactic-frame distribution, and usually what you want to use. To evaluate it at many velocities, see Performance Tips.

Measurement Uncertainties

Parameters with measurement uncertainties use Measurements.jl, as do the ephemeris constants (see Ephemerides).

  • Pointwise functions (fχ, fχlab, ...) follow the model: a model carrying Measurements gives Measurement results, and an exact one plain numbers (with the central-value ephemeris).
  • Integrals (fχspeed, g, velint, HaloIntegralProblem, ...) evaluate central values by default, since propagating through a quadrature is typically 10-130x slower; pass uncertainty = true to propagate.
  • SHM is exact, following the reporting conventions of [2]; SHMerr attaches measurement uncertainties to its speeds for sensitivity studies (not for reported limits), and SHMpp carries the uncertainties of the SHM++.

The central-value model of any HaloModel is value(m) (from Measurements.jl), which evaluates as fast as an exact model:

Measurements.value — Method
Measurements.value(m::HaloModel)

Copy m with every Measurement parameter replaced by its central value.
